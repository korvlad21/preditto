# Email sending

Reviewed: 2026-10-27. Local SMTP fixture tests passed with race detection; backend
unit tests and vet passed. No real Mail.ru delivery was attempted.

## Purpose and entry points

Owns SMTP transport and MIME composition for individual messages. Read this for
mail configuration, TLS/authentication, SMTP errors or test sends. There is no
dedicated email HTTP API or database persistence. Successful login sends a notification from the auth handler. Account
registration and credentials remain owned by [auth](auth.md).

The [setup guide](../../README.md#smtp-email) contains environment settings and
the explicit CLI test command. Compose loads `.env`; Go reads process environment.

## Behavior and constraints

- `mailer.New(config.MailConfig)` validates without network access. `Send(ctx,
  Message)` accepts one `To`, nonempty `Subject` and `Text`, and optional `HTML`.
  MIME/UTF-8 encoding, Date and Message-ID are generated by the mail library.
- Disabled mail returns `ErrDisabled`; invalid messages return
  `ErrInvalidMessage`. Header CR/LF/NUL injection is rejected. HTML is supplied
  by the caller, which must escape user-controlled template data.
- Sending uses authenticated SMTP with verified TLS 1.2 or newer. `tls` is
  implicit TLS, defaulted to Mail.ru port 465 in Compose; `starttls` requires an
  upgrade before AUTH. Authentication supports PLAIN or LOGIN. Plaintext and TLS
  verification bypasses are not configurable.
- Each send has its own client/connection, making a constructed mailer safe to
  share between callers. The caller's cancellation and configured overall timeout
  close the connection even during a stalled greeting, AUTH, DATA or STARTTLS.
- Success means SMTP accepted DATA, not inbox delivery. Post-acceptance RSET/QUIT
  failures do not change success. There is no queue or retry. A lost DATA response
  leaves acceptance uncertain; callers must account for possible duplicates.
- `mailer.Error` exposes a safe operation and SMTP status code when available;
  its string excludes server replies. Unwrapping retains the underlying library
  error or context cancellation/deadline. Never log credentials, full config
  objects, message bodies, or unwrapped server replies.

## Sources and configuration ownership

| Source | Responsibility |
| --- | --- |
| [global.go](../../backend/internal/mailer/global.go) | Process-wide Configure/Send, atomic sender publication and disabled default |
| [mailer.go](../../backend/internal/mailer/mailer.go) | Message, constructor, encrypted SMTP send and safe errors |
| [mail.go](../../backend/internal/config/mail.go) | Independent `LoadMail`, validation, disabled default |
| [config.go](../../backend/internal/config/config.go) | Includes `Mail` in API configuration; rejects invalid enabled settings |
| [mailtest](../../backend/cmd/mailtest/main.go) | Explicit recipient, optional body flags, no DB/JWT dependency |
| [Compose](../../docker-compose.yaml), [.env.example](../../.env.example) | Mail.ru defaults, backend-only mail environment and `tools`-profile CLI service |

The API calls `mailer.Configure(cfg.Mail)` once in `cmd/api/main.go`. Handlers
and services call package-level `mailer.Send` without dependency injection.
The atomic pointer makes publication and concurrent reads safe; each send takes
a snapshot of its sender. Invalid configuration leaves the prior sender intact.
Before configuration, sending returns `ErrDisabled`. Configuration is shared
process state: tests must restore disabled settings and avoid parallel overrides.
`mailer.New` remains available for private senders such as the CLI. After successful login,
the handler sends to `result.User.Email` using the request context. Errors are
logged but do not fail login; disabled mail is silently ignored. `LoadPostgres`
remains independent of mail configuration.
Mail credentials are not passed to seeds, migrations or frontend. No schema change is involved.

## Dependencies and limits

`github.com/wneessen/go-mail` is pinned at v0.6.2, compatible with the existing
Go 1.22 directive. Its dependency requirements raise `x/crypto` to v0.33.0,
`x/text` to v0.22.0 and `x/sys` to v0.30.0. Do not silently replace it with the
latest version: newer releases may require a newer Go minimum.

The library's dialing context alone does not bound the whole SMTP exchange;
the module closes its owned connection on cancellation. The library wraps send
errors in `mail.SendError`, so SMTP status extraction uses its `ErrorCode()` as
well as `textproto.Error` for connection/authentication failures. It also sends
RSET after accepting DATA; `Msg.IsDelivered()` distinguishes a subsequent reset
failure from a failed submission. Keep these behaviors covered when upgrading.

Production delivery requires authorized provider credentials/sender, working
outbound SMTP and domain setup appropriate to the provider. The local fixture
tests do not establish delivery through Mail.ru or the configured deployment.

## Verification

[Global sender tests](../../backend/internal/mailer/global_test.go) cover the
unconfigured/disabled default, preserving the sender after invalid configuration,
local TLS delivery through package-level Send, and concurrent Configure/Send.
Handler PostgreSQL tests use disabled mail or a loopback TLS failure to verify
that rejected login does not attempt sending and SMTP failure preserves tokens.


[SMTP tests](../../backend/internal/mailer/mailer_test.go) use an isolated loopback
server and trusted test certificate. They cover implicit TLS, mandatory STARTTLS,
PLAIN/LOGIN auth, UTF-8 MIME alternatives, text-only email, rejected recipients
and AUTH/DATA, certificate trust/hostname errors, absent STARTTLS, timeout,
cancellation, header injection and disconnect after DATA acceptance.

[Configuration tests](../../backend/internal/config/mail_test.go) cover disabled
defaults, validation, API loading and DB/JWT independence. [CLI tests](../../backend/cmd/mailtest/main_test.go)
cover explicit recipients and disabled sending. Run the targeted commands in
the [Go guide](../commands/topics/go.md#smtp-module-checks). Real Mail.ru delivery
requires a separate explicit test with credentials; automated tests send no
external email.
